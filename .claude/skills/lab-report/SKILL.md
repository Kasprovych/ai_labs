# Звіт лабораторної роботи

Звіт пишеться в `REPORT_LABN.md` (корінь репозиторію) і збирається командою
`.venv/bin/python scripts/build_report.py labN` у `report/REPORT_LABN.docx` та `.pdf`.

Оформлення — **автоматичне**: DOCX бере стилі з `scripts/reference_lpnu.docx`, PDF — з
`scripts/report_lpnu.css` (Times New Roman 14, інтервал 1,5, абзац 1,25 см, поля 25/15/20/20 мм).
Зразок — `REPORT_LAB2.md`: нові звіти мають виглядати так само.

## Структура файлу

Вимога завдання: титульний аркуш, мета роботи, покроковий опис ходу роботи, приклад програмної
реалізації, скріншоти з демонстрацією результатів виконання програми, висновки.

```markdown
<титульна сторінка — скопіюй блок із REPORT_LAB2.md, зміни номер і тему>

<!-- pagebreak -->

# Мета роботи
# Хід роботи
## Крок 1. Середовище та структура проєкту
## Крок 2. ...            (по кроку на кожен пункт завдання, у порядку завдання)
# Результати виконання програми      (скріншоти термінала, підсумкові таблиці й графіки, аналіз)
# Висновки                           (нумерований список із ключовими числами)
```

Титульна сторінка — pandoc-блоки `::: {custom-style="Title Header|Title Right|Title Center|Title Signature"}`.
Тему бери з назви лабораторної в завданні. `<!-- pagebreak -->` — розрив сторінки.

## Синтаксис

**Рисунок** — підпис із номером пишеться вручну в alt-тексті, ширина до 16 см:

```markdown
![Рис. 3. Збіжність генетичного алгоритму](artifacts/lab3/plots/convergence.png){width=16cm}
```

**Таблиця** — рядок `Table: Таблиця N. Назва` перед Markdown-таблицею:

```markdown
Table: Таблиця 2. Простір пошуку гіперпараметрів

| Гіперпараметр | Тип | Діапазон |
| :--- | :--- | :--- |
```

Нумерація рисунків і таблиць наскрізна й послідовна — після правок перевір її.

**Код** — лише короткі ключові фрагменти (до ~25 рядків) у блоках ```` ```python ````, перший
рядок — коментар із шляхом до файлу (`# src/evolution/genetic_algorithm.py — ...`).

**Скріншоти** — PNG з `artifacts/labN/screenshots/`, отримані рендером реального логу:
`.venv/bin/python scripts/render_terminal.py <лог> <png> --start "<рядок>" --lines 45`.

Шляхи — відносно кореня репозиторію (`artifacts/labN/...`).

## Правила змісту

- **Числа не вигадуються.** Кожне число у тексті має бути в таблицях/логах `artifacts/labN/`.
  Якщо потрібного числа немає — його має порахувати й зберегти код, а не автор звіту.
- **Кожен рисунок і таблиця** згадані в тексті та **проаналізовані**: що видно і який висновок.
- **Обґрунтування вибору.** Для кожного рішення: «обрано X, бо …; альтернатива Y гірша тут через …».
- **Покроковість.** Для кожного кроку: що зроблено → навіщо → як (метод + параметри + фрагмент
  коду) → що отримано. Для кроків зі встановленням (моделі, бібліотеки) — точні команди.
- **Чесні висновки.** Якщо метод не дав переваги або якість слабка — так і пишемо, з поясненням
  і з обмеженнями методики оцінювання.
- **Обсяг:** орієнтир 10–20 сторінок. Кілька однотипних графіків об'єднуй в один ще на рівні коду.

## Стиль

Академічний, безособовий («виконано», «побудовано», «отримано»). Англомовні назви методів — як є
(RAG, top-k, elitism), при першому вжитку з українським поясненням. Без розмовних зворотів, без
емодзі, без «ми». Десятковий роздільник — крапка, як у таблицях артефактів (так у ЛР1–2).

## Збирання і перевірка

Потрібні `pandoc` (`brew install pandoc`) і Google Chrome. Після збирання **відкрий PDF** і
переглянь кожну сторінку: рисунки чіткі й не обрізані; широкі таблиці влізли; заголовок не
лишився внизу сторінки без тексту; нумерація послідовна; титульна сторінка на одному аркуші.
