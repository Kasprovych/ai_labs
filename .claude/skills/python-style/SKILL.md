# Стиль коду ai_labs

Читач коду — Java-інженер, який вивчає Python і ML. Мета: код читається згори донизу як
пояснення, а не як головоломка. Нові лабораторні продовжують стиль ЛР1–2 (`main_lab2.py`, `src/`).

## Будова лабораторної

```
main_labN.py            # оркестратор: ЛИШЕ послідовність кроків, банери, збереження підсумків
src/config/<x>_config.py# @dataclass(frozen=True) з усіма параметрами експерименту
src/<домен>/            # по одному модулю на відповідальність; імена — за змістом
tests/test_labN_*.py    # pytest на власну логіку
artifacts/labN/         # plots/, screenshots/, таблиці .md/.csv/.json, run_output.txt
```

- **Одна відповідальність.** Клас або рахує, або малює, або зберігає. Функція, що рахує, повертає
  результат (датаклас, `DataFrame`), а не друкує його.
- **`main_labN.py` — оркестратор.** Якщо в ньому з'явився змістовний цикл чи формула — це логіка,
  винось у модуль.
- **Залежності через конструктор.** Ніяких глобальних змінних і синглтонів; конфігурацію та
  seed/`numpy.random.Generator` передавай параметрами.
- **Спільне — у спільний пакет**, не копіювати між лабораторними.

## Java-стиль засобами Python

| Потрібно | Пиши так |
|---|---|
| інтерфейс | `abc.ABC` + `@abstractmethod` (у ЛР1–2 імена з префіксом `I`: `IModelBuilder`) або `typing.Protocol` |
| незмінний DTO / record | `@dataclass(frozen=True)` |
| enum | `enum.Enum` |
| константа | `UPPER_CASE` на рівні модуля |
| private-поле / метод | префікс `_` (`self._model`, `def _fit(...)`) |
| `Optional<T>` | `T | None` |
| `List<String>`, `Map<K,V>` | `list[str]`, `dict[K, V]`; у параметрах — `Sequence`, `Mapping` |
| checked exception | власний клас винятку зі зрозумілим повідомленням |

Іменування: `snake_case` — функції, змінні, модулі; `PascalCase` — класи.

## Типи та документування

- Анотації типів на всіх параметрах і результатах.
- Docstring і коментарі — **англійською** (як у ЛР1–2), на кожному модулі, класі та публічній
  функції. Docstring пояснює **що і навіщо** (і ML-зміст методу одним-двома реченнями), коментар
  у коді — **чому саме так**. Не переказуй код словами.
- Неочевидну для Java-розробника конструкцію Python (генератор, декоратор, розпакування, зрізи,
  broadcasting у NumPy) супроводжуй коротким коментарем при першій появі в лабораторній.
- Усі числові параметри — у `src/config/` з коментарем, чому таке значення.

## Правила ML-коду

- `fit` — лише на train. Гіперпараметри — на validation. Test — один раз, наприкінці.
- Seed у кожному розбитті, моделі, генераторі випадкових чисел; `np.random.default_rng(seed)`
  замість глобального `np.random.seed`.
- Класифікація: `stratify=target`.
- pandas: без `inplace=True`; без циклів по рядках.
- Графіки: об'єктний стиль (`fig, ax = plt.subplots()`), підписані осі, `dpi=150`,
  `fig.savefig(...); plt.close(fig)`.

**Еволюційні алгоритми:** оператори (відбір, схрещування, мутація) — окремі невеликі класи або
функції, які можна тестувати ізольовано; фітнес-функція — окремий клас із кешем оцінених
розв'язків; історія поколінь зберігається як дані (DTO), графіки будуються з неї окремо;
порівняння з базовими методами — за однакового бюджету оцінювань.

**RAG:** кожен етап — окремий клас за інтерфейсом (завантаження корпусу, очищення, чанкінг,
ембедер, векторне сховище, ретривер, ре-ранкер, LLM, пам'ять діалогу, пайплайн, оцінювання);
промпти — іменовані константи в одному модулі; LLM і ембедер підміняються фейками в тестах;
важкі імпорти (`mlx_lm`, `sentence_transformers`, `chromadb`) — усередині модулів, яким вони потрібні.

## Тести

`tests/test_labN_<модуль>.py`, pytest. Тестуй власну логіку на крихітних синтетичних даних:
форму й типи результату, граничні випадки, інваріанти (межі генів, перекриття чанків, порядок
ранжування). Не тестуй sklearn і не завантажуй моделі в тестах. Назва тесту — речення:
`test_mutation_keeps_genes_within_bounds`.

## Заборонено

`from x import *` · `os.path` (є `pathlib`) · змінювані значення за замовчуванням (`def f(items=[])`) ·
голий `except:` · закоментований код · Jupyter-ноутбуки як основний код · секрети й API-ключі в коді.
`print` — лише в `main_labN.py` для банерів і таблиць (як у ЛР1–2), у модулях — `logging`.
