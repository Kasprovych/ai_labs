# ai_labs — лабораторні роботи з курсу «Штучний інтелект та інноваційні інформаційні технології»

Завдання: ЛР1–2 — глибинне навчання (TensorFlow, PyTorch), ЛР3 — еволюційні алгоритми,
ЛР4 — RAG-система (`Лабораторні роботи 3-4.pdf`). Звіти здаються викладачеві у форматі
Львівської політехніки (кафедра СШІ).

## Для кого це робиться

Автор — Java-інженер, новачок у Python і машинному навчанні. Тому:

- пояснюй терміни ML і конструкції Python простими словами, де доречно — через аналогії з Java;
- код пиши в «Java-стилі»: класи з однією відповідальністю, інтерфейси (`ABC`/`Protocol`),
  незмінні `@dataclass(frozen=True)`, залежності через конструктор, жодної «магії»;
- спілкуйся українською.

## Команди

```bash
uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python main.py              # ЛР1 (TensorFlow)
.venv/bin/python main_lab2.py         # ЛР2 (PyTorch)
.venv/bin/python main_lab3.py         # ЛР3 (генетичний алгоритм)
.venv/bin/python main_lab4.py         # ЛР4 (RAG): індексація, оцінювання, демонстрація діалогу
.venv/bin/python main_lab4.py chat    # ЛР4: інтерактивний чат
.venv/bin/python scripts/build_report.py labN        # REPORT_LABN.md -> report/REPORT_LABN.docx + .pdf
.venv/bin/python scripts/render_terminal.py ...      # «скріншот» термінала з реального логу запуску
.venv/bin/python -m pytest            # тести
```

## Структура

```
main.py, main_labN.py     оркестратор лабораторної №N: лише послідовність кроків
src/config/               незмінні dataclass-конфігурації (усі числа — тут)
src/<домен>/              логіка: data, eda, models, training, visualization (ЛР1–2),
                          evolution (ЛР3), rag (ЛР4)
artifacts/labN/           результати запуску: plots/, screenshots/, таблиці, run_output.txt
                          (ЛР1 історично пише просто в artifacts/)
REPORT_LABN.md            джерело звіту; report/REPORT_LABN.docx|pdf — зібраний звіт
docs/GUIDE_LABN.md        навчальний конспект для автора
scripts/                  збирання звіту (pandoc + headless Chrome), стилі ЛП
tests/                    pytest
data/                     датасети й корпуси (великі файли не комітяться)
```

Код, потрібний кільком лабораторним, лежить у спільному пакеті `src/<домен>/` і не копіюється.

## Як виконується лабораторна

Запуск: `/lab N` (скіл `lab`) — він веде весь конвеєр і викликає агентів:

1. `lab-planner` → `docs/PLAN_LABN.md` (чекліст вимог, ключові рішення, модулі й артефакти)
2. `ml-engineer` → код + тести + артефакти
3. `ml-reviewer` → перевірка коректності й якості коду (лише читає)
4. `tutor` → `docs/GUIDE_LABN.md` (навчальний конспект для автора)
5. `report-writer` → `REPORT_LABN.md` + DOCX/PDF

Лабораторна **готова**, коли: кожна вимога завдання закрита артефактом; `pytest` зелений;
`main_labN.py` проходить з нуля; DOCX/PDF зібрано й переглянуто очима.

## Обов'язкові правила

**Код** (деталі — скіл `python-style`):
- анотації типів і docstring на всьому публічному; ідентифікатори, docstring і коментарі —
  англійською (так написано ЛР1–2), підписи графіків — англійською або українською, але однаково
  в межах лабораторної;
- `main_labN.py` лише оркеструє, логіка — у модулях `src/`, числа — у `src/config/`.

**Коректність**:
- фіксований seed усюди; стратифіковане розбиття для класифікації;
- усе, що «вчиться» на даних, робить `fit` лише на train; гіперпараметри підбираються на
  validation, тест використовується один раз — для підсумкової оцінки;
- порівняння методів — за однакового бюджету обчислень і, де можливо, на кількох seed.

**Звіт і конспект** (скіли `lab-report`, `lab-guide`):
- жодної цифри «з голови»: числа — лише з файлів у `artifacts/labN/`;
- «скріншоти» — це рендер реального `run_output.txt`, а не вигаданий текст;
- висновки спираються на реально отримані результати, навіть якщо вони «некрасиві».

**Інше**: не коміть і не пуш без прохання; важкі залежності, завантаження великих моделей і
вибір варіанта/датасету/LLM погоджуй з автором.
